QUÉ HACE ESTO, EN CORTO
-----------------------
Hasta ahora las pantallas del Financiero leían 8 tablas "resumidas" que se
cargaron a mano desde CSV. Con esta publicación:

  1. PIQ_IA tiene una COPIA FIEL de cada una de las 8 vistas de CONTACC del
     servidor del cliente (10.10.0.6,65280): mismo nombre, mismos campos,
     mismo orden, tipos equivalentes, sin resumir nada:
         vw_piq_balance_saldos, vw_piq_balance_general, vw_catalogo_cuentas,
         vw_piq_centrosdecosto, vw_piq_presupuestos, vw_piq_asociados_cuota,
         vw_piq_cheques_circulacion, vw_piq_saldos_bancos
  2. Cada noche a las 2:00 a. m. una tarea de Windows copia esas 8 vistas
     completas (sync_financiero.py). Así el cliente tiene siempre los datos
     del día anterior de la contabilidad, como en Power BI.
  3. Las pantallas siguen leyendo BalanceSaldos, BalanceGeneral, CatalogoCuentas,
     CentrosDeCosto, Presupuestos, AsociadosCuota, ChequesCirculacion y
     SaldosBancos, pero ahora esas 8 son VISTAS calculadas sobre las copias
     fieles. El código de la web no cambia en eso.
  Si mañana hace falta un campo que ya venía del cliente, ya está en la copia
  fiel: solo hay que agregarlo a la vista, no rehacer ninguna tabla.

IMPORTANTE - SALDOS BANCARIOS Y OTROS INGRESOS NO SE SINCRONIZAN
-----------------------------------------------------------------
dbo.SaldoBancario y dbo.OtroIngreso NO vienen de la contabilidad: el cliente
manda esos datos por Excel y se cargan SOLO desde la pantalla de cargas del
sistema (mantenimiento de carga), igual que Importaciones, Plaguicidas y
Nutrientes. Esta publicación NO las toca: ni los scripts SQL, ni la
sincronización nocturna, ni las cargas por Excel. Quedan exactamente como
están hoy, con los datos que ya se cargaron.

REGLAS DE SEGURIDAD DEL SINCRONIZADOR
-------------------------------------
  - Para cada vista lee TODO el origen a una tabla temporal de staging y
    recién cuando la lectura terminó completa reemplaza la copia, en UNA
    transacción. Si falla la conexión o la lectura o el reemplazo, la copia
    conserva los datos del día anterior (nunca queda vacía ni a medias).
  - Si una vista falla, las demás siguen.
  - Si el origen devuelve 0 filas y la copia tenía datos, NO la reemplaza.
  - Reintenta cada vista 2 veces (espera 60 s) por si la VPN se cae un instante.
  - NO toca Importacion, Nutrientes, catálogos, CatalogoAgrupadorCuentas,
    SaldoBancario, OtroIngreso, Usuarios ni Roles.

 PASO 3 - AGREGAR VARIABLES AL .env
====================================================================

Archivo: C:\Pronostiq\Agrequima-pronostiq\.env  (el MISMO del backend, el de la
raíz; NO el de deploy\). Ya tiene DB_SERVER, DB_NAME, DB_USER, DB_PASSWORD y
ODBC_DRIVER: son el DESTINO (PIQ_IA) y el sincronizador las reutiliza tal cual
(ese usuario tiene que poder crear/borrar tablas en PIQ_IA, como hoy).

Agregar AL FINAL, una por línea, sin comillas y sin espacios alrededor del "=":

   SYNC_CONTACC_DB_SERVER=10.10.0.6,65280
   SYNC_CONTACC_DB_NAME=CONTACC
   SYNC_CONTACC_DB_USER=<usuario de SOLO LECTURA que dio el cliente>
   SYNC_CONTACC_DB_PASSWORD=<su contraseña>

Formato: la coma de "10.10.0.6,65280" es parte del valor (IP,puerto). Si la
contraseña tiene espacios, o un " #" (espacio y numeral), ponerla entre
comillas simples: SYNC_CONTACC_DB_PASSWORD='mi clave #1'.

Opcionales (los valores indicados son los que ya usa por defecto):

   SYNC_FINANCIERO_REINTENTOS=2       (intentos por vista)
   SYNC_FINANCIERO_ESPERA_SEG=60      (espera entre intentos)
   SYNC_FINANCIERO_LOG_DIR=C:\Pronostiq\Agrequima-pronostiq\logs

 CÓMO VOLVER ATRÁS SI ALGO FALLA
====================================================================

Cada nivel es independiente; usar solo el que haga falta.

A. Parar la sincronización nocturna (no toca datos):
       Disable-ScheduledTask -TaskName PIQ_IA_Sync_Financiero

B. Devolver las 8 tablas resumidas originales (deshacer el paso 7). En SSMS:
       BEGIN TRY
           SET XACT_ABORT ON;
           BEGIN TRANSACTION;
           IF OBJECT_ID('dbo.BalanceSaldos', 'V') IS NOT NULL AND OBJECT_ID('dbo.BalanceSaldos_respaldo', 'U') IS NOT NULL
               BEGIN DROP VIEW dbo.BalanceSaldos; EXEC sp_rename 'dbo.BalanceSaldos_respaldo', 'BalanceSaldos'; END
           (repetir el mismo bloque IF para BalanceGeneral, CatalogoCuentas, CentrosDeCosto,
            Presupuestos, AsociadosCuota, ChequesCirculacion y SaldosBancos)
           COMMIT TRANSACTION;
       END TRY
       BEGIN CATCH
           IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION;
           THROW;
       END CATCH
   (Está completo y listo para descomentar al final de 18_vistas_financiero.sql.)
   Con esto la web vuelve a leer las tablas viejas con la carga manual del 2 de octubre.

C. Volver los archivos: borrar los copiados en el paso 2 y restaurar
   C:\Pronostiq\Backups\deploy_antes_sync\ y app_scripts_antes_sync\ (y el .env

Las tablas dbo.*_respaldo, dbo.*_previa y las copias vw_piq_* no molestan; se
pueden borrar a mano cuando todo esté verificado.
