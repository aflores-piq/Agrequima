====================================================================
 PIQ_IA - Instrucciones de instalacion en este servidor
====================================================================

Esta carpeta trae todo lo necesario para instalar, en ESTE servidor,
la base de datos PIQ_IA y su sincronizacion nocturna, sin necesitar
ayuda tecnica en vivo. Segui los pasos EN ORDEN. Cada paso dice
exactamente que click hacer.

Archivos que vas a usar:
  01_crear_base_piq_ia.sql       -> lo abris en SQL Server Management Studio (SSMS)
  02_seed_roles_y_admin.sql      -> lo abris tambien en SSMS, despues del anterior
  03_cargar_datos_iniciales.sql  -> lo abris tambien en SSMS, despues del anterior
  04_migracion_nutrientes_tipo_exclusion.sql -> lo abris tambien en SSMS, cuando corresponda (ver Paso 3B)
  05_fix_colacion_usp_cargarnutrientes.sql   -> lo abris tambien en SSMS, si ves el error de collation al cargar Nutrientes (ver Paso 3C)
  06_fix_colacion_procedimientos_restantes.sql -> lo abris tambien en SSMS, preventivo -- mismo error en Plaguicidas/Nomenclatura/Agrupador (ver Paso 3D)
  generar_hash_password.py       -> genera el valor que necesita 02_seed_roles_y_admin.sql
  sync_piq_ia.py                 -> el programa que trae los datos cada noche
  .env.ejemplo                   -> plantilla de configuracion (la vas a copiar y completar)
  requirements.txt                -> lista de librerias de Python que hace falta instalar

No hace falta editar sync_piq_ia.py en ningun paso -- toda la
configuracion va en el archivo ".env" que vas a crear en el Paso 5.


====================================================================
 PASO 0 -- Que necesita tener este servidor
====================================================================

- SQL Server Management Studio (SSMS): para los Pasos 1, 2 y 3.
- Python 3.10 o mas nuevo: para el Paso 2 en adelante (generar el hash
  de la contraseña ya necesita Python).
  Para revisar si ya esta instalado: abrir el Simbolo del sistema
  (Inicio > escribir "cmd" > Enter) y escribir:
        python --version
  Si responde con un numero (ej. "Python 3.12.4"), ya esta instalado,
  segui al Paso 1. Si dice "no se reconoce el comando" o similar, no
  esta instalado -- lo instalas asi:
    1. Ir a https://www.python.org/downloads/
    2. Descargar la version para Windows (el boton amarillo grande).
    3. Ejecutar el instalador. IMPORTANTE: en la primera pantalla del
       instalador, marcar el check "Add python.exe to PATH" (abajo de
       todo) ANTES de darle a "Install Now".
    4. Cuando termine, cerrar y volver a abrir el Simbolo del sistema,
       y repetir "python --version" para confirmar que ahora si
       responde.

- El driver "ODBC Driver 17 for SQL Server" (o 18): para revisar si ya
  esta instalado, abrir "Orígenes de datos ODBC (64 bits)" (buscarlo en
  el menu Inicio) y fijarse en la pestaña "Controladores" si aparece
  "ODBC Driver 17 for SQL Server" o "ODBC Driver 18 for SQL Server" en
  la lista. Si no aparece ninguno de los dos, descargarlo de:
        https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server
  (Si instalas la version 18 en vez de la 17, avisá -- hay que ajustar
  un valor en el .env, ver Paso 5.)


====================================================================
 PASO 1 -- Crear la base de datos PIQ_IA (con SSMS)
====================================================================

1. Abrir SQL Server Management Studio.
2. En la ventana de conexion, poner el nombre del servidor de SQL
   Server de ESTA maquina (si no lo sabés, normalmente es el nombre de
   la PC, o "localhost", o "localhost\SQLEXPRESS" si es una instancia
   con nombre) y conectarse (autenticacion de Windows o SQL, la que
   uses normalmente en este servidor).
3. Menu "Archivo" > "Abrir" > "Archivo..." y elegir el archivo
   "01_crear_base_piq_ia.sql" de esta carpeta.
   (Alternativa: arrastrar el archivo directo a la ventana de SSMS.)
4. Con el script abierto, presionar la tecla F5 (o el botón
   "¡ Ejecutar" con el triangulito verde, arriba a la izquierda).
5. Esperar a que termine (unos segundos). Abajo, en la pestaña
   "Mensajes", revisar que:
   - No haya ninguna linea en color ROJO (eso indicaria un error).
   - Al final aparezcan dos tablas de resultados: una con 13 filas
     (los nombres de las tablas creadas, todas con 0 en la columna
     "filas" -- es normal, todavia no hay datos) y otra con 4 filas
     (los nombres de los stored procedures creados).
   - La ultima linea debe decir:
     "=== Script de creacion de PIQ_IA finalizado. Revisa que no haya
     errores en rojo arriba. ==="

Si algo salio mal: es seguro volver a correr el script las veces que
haga falta (esta escrito para no duplicar ni borrar nada si algo ya
existe). Si el error persiste, copiar el mensaje en rojo exacto para
poder diagnosticarlo.

Listo -- la base PIQ_IA ya existe, con su estructura completa, pero
sin datos ni usuarios todavia (eso lo traen el Paso 2, el Paso 3 y el
Paso 7).


====================================================================
 PASO 2 -- Crear los roles y el usuario administrador (con SSMS)
====================================================================

Este paso deja PIQ_IA lista para poder iniciar sesión en la app apenas
esté instalada -- crea los 3 roles del sistema y UN usuario
administrador de producción.

1. Generar el hash de la contraseña (nunca se escribe la contraseña
   real en ningún archivo, solo el resultado de este paso):
   a. Abrir el Simbolo del sistema (Inicio > escribir "cmd" > Enter).
   b. Escribir:
        cd "C:\ruta\donde\copiaste\esta\carpeta"
        pip install bcrypt
        python generar_hash_password.py
   c. Va a pedir la contraseña dos veces (no se ve en pantalla
      mientras se escribe, es normal). Escribir la contraseña real que
      va a usar el administrador de producción.
   d. Va a mostrar una línea larga que empieza con algo como
      '$2b$12$...' -- ese es el hash. Seleccionarlo y copiarlo
      completo (con las comillas simples incluidas).

2. Abrir "02_seed_roles_y_admin.sql" (de esta carpeta) en SSMS, igual
   que en el Paso 1 (Archivo > Abrir, o arrastrarlo a la ventana).

3. Buscar, cerca del principio del archivo, estas tres líneas (usar
   Ctrl+B o Ctrl+F para buscar "PONÉ ACÁ" si cuesta encontrarlas):

        DECLARE @NombreUsuario VARCHAR(100) = '[PONÉ ACÁ EL NOMBRE DE USUARIO PARA INICIAR SESIÓN, ej. admin]';
        DECLARE @Email         VARCHAR(200) = '[PONÉ ACÁ TU CORREO PARA PRODUCCIÓN]';
        DECLARE @PasswordHash  VARCHAR(255) = '[PEGÁ ACÁ EL HASH QUE TE DIO generar_hash_password.py]';

   Reemplazar el texto entre comillas de las tres líneas:
   - @NombreUsuario: el nombre con el que se va a iniciar sesión (no
     tiene que ser el correo, ej. "admin").
   - @Email: el correo real de esa cuenta.
   - @PasswordHash: pegar ahí el hash completo que copiaste en el
     paso 1.d (reemplazando todo el texto "[PEGÁ ACÁ ...]", comillas
     simples incluidas al principio y al final).

4. Presionar F5 (o "¡ Ejecutar") con la conexión a PIQ_IA activa
   (fijarse arriba en SSMS que la barra de "Base de datos disponible"
   diga "PIQ_IA" y no "master" ni otra).

5. En la pestaña "Mensajes", confirmar:
   - Una tabla con los 3 roles (Administrador, Usuario, Administrador
     de Usuarios).
   - El mensaje "Usuario administrador creado: <el nombre que
     pusiste>".
   - Una segunda tabla mostrando esa cuenta recién creada, con
     Activo=1 y PuedeExportar=1.

   Si en cambio aparece "FALTA COMPLETAR LOS VALORES DE ARRIBA...", es
   que alguna de las 3 líneas del paso 3 se quedó con el texto
   "[PONÉ ACÁ...]" / "[PEGÁ ACÁ...]" sin reemplazar -- revisar y volver
   a correr el script.

   Si aparece "Ya existe un usuario con ese NombreUsuario...", ya
   habías corrido este paso antes con ese mismo nombre de usuario --
   es seguro, no se duplica ni se pisa la cuenta existente.

Con la contraseña que usaste en el paso 1.c ya podés iniciar sesión en
la app (una vez que esté instalada y corriendo) con el usuario que
elegiste.


====================================================================
 PASO 3 -- Cargar los datos iniciales (Importacion, Nutrientes,
 catálogos) -- con SSMS
====================================================================

Este paso trae, en un solo archivo, TODOS los datos reales que ya
estaban cargados en la base de origen (Importacion, Nutrientes, y los
2 catálogos de agrupación) -- para que PIQ_IA arranque con información
real desde el primer día, sin esperar a la primera corrida nocturna de
sincronización.

1. Abrir "03_cargar_datos_iniciales.sql" (de esta carpeta) en SSMS,
   igual que los dos pasos anteriores (Archivo > Abrir, o arrastrarlo
   a la ventana) -- es un archivo grande (~10 MB), puede tardar unos
   segundos en abrir.

2. Presionar F5 (o "¡ Ejecutar") con la conexión a PIQ_IA activa
   (igual que en el Paso 2, fijarse que diga "PIQ_IA" arriba, no
   "master"). Esto puede tardar uno o dos minutos -- es normal, son
   más de 30,000 filas.

3. En la pestaña "Mensajes", confirmar 4 líneas "OK: <tabla> cargada
   (### filas)" -- una por cada tabla (Importacion, Nutrientes,
   CatalogoNomenclaturaPlaguicidas, CatalogoAgrupadorNutrientes) -- y,
   al final, una tabla de resultados con el conteo final de cada una.

   Si en cambio aparece "ERROR al cargar <tabla>: ...", anotar el
   mensaje completo -- ese texto dice exactamente qué salió mal en esa
   tabla puntual. Las demás tablas no se ven afectadas por el error de
   una sola (cada una se carga por separado).

Es seguro volver a correr este script las veces que haga falta: cada
tabla se vacía (TRUNCATE) antes de volver a insertar sus datos, así
que nunca duplica filas -- si algo salió mal a mitad de camino, correr
de nuevo el archivo completo lo deja bien.

Este script NO toca Roles ni Usuarios -- eso ya quedó bien en el Paso
2 y no se pisa acá.


====================================================================
 PASO 3B -- Migración: exclusión de productos y corrección de Tipo en
 Nutrientes (agregado después del despliegue inicial -- con SSMS)
====================================================================

Este paso corrige, sobre los datos ya cargados en el Paso 3, dos cosas
que se descubrieron después de que Nutrientes ya estaba funcionando:

  - 29 productos que en realidad son plaguicidas (Glifosato, Atrazina,
    etc.) se habían colado en el diccionario de Nutrientes -- el
    cliente confirmó que no corresponden ahí. Este script agrega una
    columna Excluido y la marca en esos productos y en las filas de
    Nutrientes ya cargadas que los mencionan (dejan de mostrarse en
    dashboards/exports, pero el dato crudo NO se borra).
  - Tipo="." (o vacío) en Nutrientes significa "Licencias" -- antes se
    dejaba tal cual por no saber qué significaba; ahora se corrige.

1. Abrir "04_migracion_nutrientes_tipo_exclusion.sql" (de esta carpeta)
   en SSMS, igual que los Pasos 1-3 (Archivo > Abrir, o arrastrarlo a
   la ventana).

2. Presionar F5 (o "¡ Ejecutar") con la conexión a PIQ_IA activa
   (fijarse arriba en SSMS que diga "PIQ_IA", no "master").

3. En la pestaña "Mensajes", revisar que no haya ninguna línea en
   ROJO. Al final aparece una tabla con 5 filas (conteos de
   verificación) -- comparar contra los valores de referencia que trae
   el propio encabezado del archivo (216 filas de Nutrientes con
   Excluido=1, 5,750 filas de Tipo corregidas, en la base de
   desarrollo). Si en PIQ_IA los números salen menores, es
   probablemente normal (PIQ_IA puede tener menos historial cargado
   todavía que la base de desarrollo) -- lo que sí hay que revisar es
   que "Filas con Tipo=\".\" o vacío restantes" dé 0 y que "Productos
   Excluido=1" dé 29.

Es seguro volver a correr este script las veces que haga falta: agrega
la columna solo si no existe, y los UPDATE solo tocan filas que
todavía no tienen el valor correcto.


====================================================================
 PASO 3C -- Fix de collation en usp_CargarNutrientes (correr SOLO si
 al cargar Nutrientes aparece un error mencionando "collation conflict"
 -- con SSMS)
====================================================================

Si al subir un archivo de Nutrientes desde la pantalla de Carga
aparece un error 500 y en stderr.log del servidor aparece algo como:

    pyodbc.ProgrammingError: [...] Cannot resolve the collation
    conflict between "SQL_Latin1_General_CP1_CI_AS" and
    "Modern_Spanish_CI_AS" in the equal to operation. (468)

es porque el collation por defecto de esta base (heredado de la
instancia de SQL Server de este servidor) no coincide con el
collation fijo que traen las columnas del catálogo de nutrientes. Este
paso lo corrige de forma permanente.

1. Abrir "05_fix_colacion_usp_cargarnutrientes.sql" (de esta carpeta)
   en SSMS, igual que los pasos anteriores.

2. Presionar F5 (o "¡ Ejecutar") con la conexión a PIQ_IA activa.

3. En la pestaña "Mensajes", confirmar que no haya ninguna línea en
   ROJO y que aparezca "usp_CargarNutrientes actualizado con COLLATE
   DATABASE_DEFAULT.".

4. Volver a intentar la carga del archivo de Nutrientes que había
   fallado, desde la pantalla de Carga -- ya debería funcionar.

Es seguro volver a correr este script las veces que haga falta:
reemplaza la definición completa del procedimiento cada vez, sin
depender de ningún estado previo.


====================================================================
 PASO 3D -- Fix PREVENTIVO de collation en Carga de Plaguicidas y en
 Nomenclatura/Agrupador (mismo problema del Paso 3C, en 3 procedimientos
 más -- con SSMS)
====================================================================

El Paso 3C corrigió el error de collation solo en usp_CargarNutrientes.
El mismo problema existe, sin haber fallado todavía, en otros 3
procedimientos: la carga de Plaguicidas (usp_CargarImportacion) y las
actualizaciones de catálogo de Nomenclatura y de Agrupador de
Nutrientes (usp_ActualizarNomenclatura, usp_ActualizarAgrupadorNutrientes).
No hace falta esperar a que fallen -- correlo ahora mismo, es
preventivo.

1. Abrir "06_fix_colacion_procedimientos_restantes.sql" (de esta
   carpeta) en SSMS, igual que los pasos anteriores.

2. Presionar F5 (o "¡ Ejecutar") con la conexión a PIQ_IA activa.

3. En la pestaña "Mensajes", confirmar que no haya ninguna línea en
   ROJO y que aparezcan las 3 líneas de confirmación (una por cada
   procedimiento) más "Fix de collation aplicado a los 3 procedimientos
   restantes.".

Es seguro volver a correr este script las veces que haga falta: mismo
motivo que el Paso 3C.


====================================================================
 PASO 4 -- Instalar las librerias de Python
====================================================================

1. Abrir el Simbolo del sistema (Inicio > escribir "cmd" > Enter).
2. Escribir el siguiente comando y presionar Enter (reemplazando la
   ruta si copiaste esta carpeta a otro lugar):

        cd "C:\ruta\donde\copiaste\esta\carpeta"

3. Escribir y ejecutar:

        pip install -r requirements.txt

4. Esperar a que termine de instalar (puede tardar uno o dos minutos).
   Si al final no aparece ningun mensaje en rojo que diga "ERROR", ya
   quedo instalado.

(Si ya instalaste "bcrypt" a mano en el Paso 2, no pasa nada -- este
comando también lo instala, y si ya está no lo reinstala.)


====================================================================
 PASO 5 -- Configurar la conexion (el archivo .env)
====================================================================

1. En esta misma carpeta, hacer una copia del archivo ".env.ejemplo"
   y renombrarla a ".env" (sin ".ejemplo", y sin ".txt" al final --
   Windows a veces agrega ".txt" solo, hay que sacarlo).

2. Abrir el archivo ".env" (recien creado) con el Bloc de notas
   (click derecho > Abrir con > Bloc de notas) y completar estos
   valores:

   SYNC_ORIGEN_DB_SERVER   -> la direccion del servidor de donde vienen
                              los datos. Hoy la unica direccion real
                              que tenemos del cliente es "10.10.0.6,65280"
                              -- OJO: todavia no se confirmo que se
                              pueda llegar a esa direccion desde este
                              servidor, ni que la base tenga las mismas
                              tablas. Si no hay conexion o las tablas
                              son distintas, avisar antes de usar esto
                              en produccion.
   SYNC_ORIGEN_DB_NAME     -> el nombre de la base de datos ahi (sin
                              confirmar todavia cual es en el servidor
                              real del cliente).
   SYNC_ORIGEN_DB_USER     -> usuario de SQL Server para conectarse ahi.
   SYNC_ORIGEN_DB_PASSWORD -> contraseña de ese usuario.

   SYNC_DESTINO_DB_SERVER  -> el servidor de SQL Server de ESTE mismo
                              servidor (normalmente "localhost").
   SYNC_DESTINO_DB_NAME    -> dejar "PIQ_IA" (ya se llama asi, Paso 1).
   SYNC_DESTINO_DB_USER    -> usuario de SQL Server de este servidor.
   SYNC_DESTINO_DB_PASSWORD-> su contraseña.

   ODBC_DRIVER             -> dejar "ODBC Driver 17 for SQL Server" tal
                              cual, SALVO que en el Paso 0 hayas
                              instalado la version 18 -- en ese caso,
                              cambiar esta linea a:
                              ODBC_DRIVER=ODBC Driver 18 for SQL Server

   SYNC_TABLAS             -> dejar tal cual viene (ya trae las 4
                              tablas correctas). Solo se toca si en el
                              futuro se agregan tablas de otros
                              proyectos (Financiero, Indicadores).

3. Guardar el archivo (Ctrl+S) y cerrarlo.

Esta es la UNICA seccion que va a cambiar mas adelante, cuando se
confirme el acceso real al cliente: los 4 valores de
"SYNC_ORIGEN_DB_*". Todo lo demas se configura una sola vez.

Nota: el Paso 3 ya cargó los datos iniciales una vez -- este script de
sincronización (una vez programado en el Paso 7) es el que los va a
mantener actualizados noche a noche después.


====================================================================
 PASO 6 -- Probar el script de sincronizacion a mano (antes de programarlo)
====================================================================

1. En el mismo Simbolo del sistema del Paso 4 (con la carpeta ya
   seleccionada con "cd"), escribir:

        python sync_piq_ia.py

2. Deberia aparecer algo asi (los numeros de filas van a ser distintos):

        === Iniciando sincronización PIQ_IA (4 tablas configuradas) ===
        OK   Importacion                              #### filas
        OK   Nutrientes                                #### filas
        OK   CatalogoNomenclaturaPlaguicidas            ### filas
        OK   CatalogoAgrupadorNutrientes                ### filas
        === Sincronización PIQ_IA finalizada (OK) ===

   Si en cambio aparece un mensaje que empieza con "ERROR" o
   "Traceback", algo fallo -- ver la seccion de PROBLEMAS FRECUENTES
   mas abajo, o copiar el mensaje completo para diagnosticarlo.

3. Verificacion en SSMS: conectarse a la base PIQ_IA y correr:

        SELECT COUNT(*) FROM dbo.Importacion;
        SELECT COUNT(*) FROM dbo.Nutrientes;
        SELECT * FROM dbo.SyncLog ORDER BY LogId DESC;

   Las dos primeras deben devolver un numero mayor a cero. La tercera
   muestra el historial de corridas (fecha, tabla, filas copiadas,
   estado) -- debe tener 4 filas nuevas con Estado = 'OK'.

Una vez que esto funciona a mano, segui al Paso 7 para programarlo.


====================================================================
 PASO 7 -- Crear la tarea programada de Windows (corre sola cada noche)
====================================================================

Esto usa el "Programador de tareas" de Windows (no SQL Server Agent).

1. Inicio > escribir "Programador de tareas" > Enter (o "Task
   Scheduler" si Windows esta en ingles).
2. En el panel de la derecha, click en "Crear tarea..." (NO "Crear
   tarea basica", esa version tiene menos opciones).
3. Pestaña "General":
   - "Nombre": escribir "PIQ_IA_Sync_Nocturno".
   - Mas abajo, marcar el circulo "Ejecutar tanto si el usuario inició
     sesión como si no" (esto es importante: así corre aunque nadie
     haya iniciado sesión en el servidor a esa hora).
   - Si esta disponible, tildar tambien "Ejecutar con los privilegios
     más altos".
   - Click en "Cambiar usuario o grupo..." y escribir "SYSTEM" (o
     "SISTEMA" en español) si querés que corra con la cuenta del
     sistema (no pide contraseña y siempre esta disponible). Si
     preferís que corra con tu propio usuario, dejalo como está, pero
     al guardar la tarea Windows te va a pedir tu contraseña de
     Windows una sola vez -- ingresarla ahi.
4. Pestaña "Desencadenadores" (Triggers):
   - Click "Nuevo...".
   - "Iniciar la tarea": elegir "Según una programación".
   - Elegir "Diariamente".
   - En "Inicio", poner la hora deseada (sugerido: 02:00, dos de la
     madrugada).
   - Dejar "Repetir cada: 1 días".
   - Click "Aceptar".
5. Pestaña "Acciones":
   - Click "Nueva...".
   - "Acción": dejar "Iniciar un programa".
   - "Programa o script": buscar y elegir el archivo python.exe. Si no
     sabés la ruta exacta, en el Simbolo del sistema escribir:
        where python
     y copiar la ruta completa que aparece (algo como
     "C:\Python312\python.exe" o similar).
   - "Agregar argumentos (opcional)": escribir
        sync_piq_ia.py
   - "Iniciar en (opcional)": escribir la ruta completa de ESTA
     carpeta (donde está sync_piq_ia.py), por ejemplo:
        C:\ruta\donde\copiaste\esta\carpeta
     (Este campo es importante -- si se deja vacío, el script no va a
     encontrar el archivo ".env" ni va a poder escribir el log.)
   - Click "Aceptar".
6. Pestaña "Condiciones": revisar que NO esté marcado "Iniciar la
   tarea solo si el equipo está conectado a la corriente alterna" (si
   es un servidor, no aplica, pero por las dudas destildarlo).
7. Pestaña "Configuración": tildar "Ejecutar la tarea lo antes posible
   si se perdió un inicio programado" (por si el servidor estaba
   apagado a la hora programada).
8. Click "Aceptar" al final. Si elegiste correr con tu propio usuario
   (no SYSTEM), va a pedir la contraseña de Windows de ese usuario --
   ingresarla y confirmar.

La tarea ya deberia aparecer en la lista principal del Programador de
tareas, con Estado "Listo".


====================================================================
 PASO 8 -- Probar que la tarea programada funciona de verdad
====================================================================

No hace falta esperar a la noche para confirmar que quedo bien armada:

1. En el Programador de tareas, click derecho sobre
   "PIQ_IA_Sync_Nocturno" > "Ejecutar".
2. Esperar unos segundos (puede tardar hasta un minuto), despues
   presionar F5 (Actualizar) en la ventana del Programador.
3. Mirar la columna "Resultado de la última ejecución": debe decir
   "La operación se completó correctamente (0x0)". Si dice otra cosa
   (un numero distinto de 0x0), algo fallo al correr desde la tarea
   (aunque haya funcionado a mano en el Paso 6) -- revisar que la ruta
   de "Iniciar en" del Paso 7 sea exactamente la de esta carpeta.
4. Confirmar en SSMS que `dbo.SyncLog` tiene filas nuevas con una
   fecha/hora reciente (la consulta del Paso 6, punto 3).

Con esto, PIQ_IA queda funcionando sola, actualizándose cada noche,
sin necesitar que nadie la corra a mano.


====================================================================
 PROBLEMAS FRECUENTES
====================================================================

"No module named 'pandas'" (o sqlalchemy, pyodbc, dotenv, bcrypt)
  -> El Paso 4 no se completo. Volver a correr:
        pip install -r requirements.txt

"Faltan variables de entorno SYNC_..._DB_{...} en el .env"
  -> El archivo ".env" no existe o le falta completar algun valor.
     Revisar el Paso 5 (¿se llama exactamente ".env", no
     ".env.ejemplo" ni ".env.txt"?).

"Login failed for user ..." / "No se puede abrir la base de datos..."
  -> El usuario o la contraseña de SYNC_ORIGEN_DB_* o
     SYNC_DESTINO_DB_* está mal, o ese usuario no tiene permiso sobre
     esa base. Confirmar las credenciales.

"No route to host" / el script se queda "colgado" mucho tiempo y
despues falla
  -> No hay conectividad de red hacia SYNC_ORIGEN_DB_SERVER (por
     ejemplo, si todavía no está armada la VPN hacia el cliente).
